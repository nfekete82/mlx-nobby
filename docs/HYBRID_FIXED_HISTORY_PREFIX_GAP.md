# Exact-prefix gap diagnosis with fixed history

## Verified finding

After identical-history replay, OFF, SPLIT_ONLY and ON all missed the
turn-three cache (0 matched tokens), even though the original
self-generated-history benchmark showed SPLIT_ONLY/ON hits of 725 tokens.
Therefore the successful self-generated-history result cannot establish a
cache speedup **for the same input conversation**.

The first-turn answer still differs in OFF versus SPLIT_ONLY/ON
(1805 vs 1370 chars), before any cache reuse. SPLIT_ONLY and ON
generated byte-identical first-turn output. The additional prefill
segmentation is a leading suspect, not yet proven a mathematical error.

## Numeric-only prefix diagnosis

The three-mode runner now supports `--diagnose`, which enables and later
restores `NOBBY_HYBRID_CACHE_DIAG` along with other experimental flags.
It records the previous full checkpoint length, third-turn common prefix
length, how far the full checkpoint extends past the common prefix, and
whether the hypothetical boundary 160 tokens earlier lies within the
common prefix. This last check is only a **prediction**: it cannot verify
that a real early cache entry exists, survived eviction or was selected.

```bash
cd ~/mlx-web
git fetch origin
git switch --track origin/diag/hybrid-fixed-history-prefix-gap

./test-venv/bin/python -m pytest -q \
  tests/test_hybrid_fixed_history_prefix_gap.py \
  tests/test_benchmark_chat_cache.py \
  tests/test_hybrid_prefill_causal.py \
  tests/test_cache_response_parity.py \
  tests/test_hybrid_cache_diagnostics.py \
  tests/test_hybrid_early_checkpoint.py \
  tests/test_hybrid_apc_dflash_runtime.py

./test-venv/bin/python -m py_compile \
  scripts/benchmark-chat-cache-causal.py \
  scripts/benchmark-chat-cache.py

./runtime-venv/bin/python \
  scripts/hybrid_apc_dflash_runtime.py --check-only

python3 scripts/benchmark-chat-cache-causal.py \
  --confirm-restarts --capture-answers --fixed-history --diagnose
```

The command restarts MLX four times including restoration. Run only when
no other inference jobs are active. Raw answers stay in owner-only
local JSON files, not in GitHub. The diagnostic log contains only numeric
metadata and no token IDs or input text.

### How to read it

For each mode inspect `prefix_gap_diagnostics`:

- `previous_full_checkpoint_tokens`: the token length of turn two's
  full checkpoint.
- `turn3_common_prefix_tokens`: shared beginning of the turn-two
  checkpoint and the third turn's new input.
- `turn3_prefix_gap_tokens`: minimum backward shift required for an
  otherwise identical full checkpoint to fit that common prefix.
- `hypothetical_early_boundary_tokens`: prior checkpoint minus the
  current 160-token margin, without verifying manager retention.
- `hypothetical_early_within_common_prefix`: whether that hypothetical
  prefix length could match, assuming semantic hash and tokenization
  stability.

If the third-turn prefix gap exceeds 160 tokens, the current early
boundary is too late to be reused even with correct snapshot storage.
If the prefix fits but lookup still misses, inspect cache-manager
retention, semantic hash and actual store calls; do **not** tune the
160-token margin blindly.

Early checkpoint remains disabled by default. This is a diagnostic
branch stacked on earlier experimental branches and **not approved to
merge as a production performance improvement**.
