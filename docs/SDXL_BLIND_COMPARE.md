# Safely compare Lustify Endgame and Juggernaut XL from Terminal

**Use this script, not `scripts/benchmark-sdxl-models.py`, on the 48 GiB Mac.**
The legacy script launches unmanaged standalone SDXL workers and bypasses the
image-service runtime lease and active unified-memory guard.

```bash
cd ~/mlx-web
./image-venv/bin/python scripts/compare-sdxl-safe.py \
  --size 512 --steps 20 --cfg 3.5 --seed 42
```

This uses four fixed photographic motifs (portrait, full-body anatomy,
interior, dynamic action), each generated by **both** SDXL models with the
same prompt, seed, size, CFG and steps. Eight requests run **sequentially**
through the already-running local `http://127.0.0.1:8030/generate` API, so
the usual chat unload/restore, MPS hard watermark, CPU offloading and
global RAM/swap watchdog remain active.

The output folder is printed, under
`~/.config/mlx-web/benchmarks/sdxl-blind/<timestamp>/` by default.
`blindvergleich.jpg` is an anonymous 2-column A/B image contact sheet;
`aufloesung.json` holds the hidden model-to-label mapping and
`laufzeiten.json` the API wall times. Once rated, reveal with:

```bash
./image-venv/bin/python scripts/compare-sdxl-safe.py --reveal '/exact/output/directory'
```

For a custom terminal image prompt:

```bash
./image-venv/bin/python scripts/compare-sdxl-safe.py \
  --prompt "Photorealistic portrait of an adult in natural window light" \
  --size 512 --steps 20 --cfg 3.5 --seed 42
```

Use repeated `--prompt` flags for multiple scenes. Run with `--dry-run`
to print the planned jobs without touching RAM or GPUs. Optional
`--size 640`, then `--size 768` can test detail at higher resolution
once 512 is validated. Image generation may fail safely if memory limits
are reached. Never disable the MPS watermark to bypass an OOM.

The first comparison uses the **same CFG 3.5** for strict A/B fairness.
The models' preferred individual CFG settings (Ragnarok 5, Lustify 3.5)
should be assessed separately after this initial blind comparison.

## Startup health check

`launchctl kickstart -k` is asynchronous: it may return before Uvicorn binds
to `127.0.0.1:8030`. The benchmark now probes `GET /health` for up to
45 seconds **before creating the run directory**, then starts the first job
only once the guarded image service is reachable. It does not spawn its own
SDXL worker. For persistent startup failures, run:

```bash
./scripts/mlx services
launchctl print "gui/$(id -u)/de.nobby.mlx-images" | tail -n 35
tail -n 80 ~/.config/mlx-web/image-error.log
```
