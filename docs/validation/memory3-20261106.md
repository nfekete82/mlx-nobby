# Memory 3 validation — 2026-11-06

All new fixtures and published results contain fictional data. Production
chats, source vaults, model settings and services were not changed or scanned.

## Reproducible A/B

The same `scripts/benchmark-memory3.py` and frozen
`tests/fixtures/memory3_retrieval.json` ran against an exported clean base
`cd5f977a438083033de6fefb0fcef3b18b920479` and the improved checkout. Each
database contains eight explicit source reports plus 2,000 fictional distractor
facts. There are 32 positive DE/EN/HU queries and three negative controls.
Embeddings and live extraction/answer models are deliberately unavailable.
Each retrieval is repeated three times; context timings include separate
fast-path queries and 32 ordinary chat-enrichment calls. Raw timings vary with
concurrent CPU/browser activity.

Evidence: [base JSON](memory3-20261106/baseline.json),
[improved JSON](memory3-20261106/improved.json). Precision@5 uses a fixed
denominator of five with one labeled relevant source per query; retrieving
exactly that source still scores 0.2. Some broader project questions legitimately
have another useful source not labeled relevant by this small fixture.

This is a **development regression set used while implementing the change**,
not a blinded semantic benchmark. It establishes the stated synthetic cases,
not 95% recall on arbitrary personal history. Three additional unseen compound
forms are tested independently of the concept families. A mocked-vector test
exercises the true hybrid branch, paraphrase-only retrieval, source privacy,
bounded query timeouts, cache reuse and deletion after caching; it does not
measure the quality of the real embedding model.

## Validation runs and regressions

- Initial sandboxed full Python run: 4,077 passed, 472 subtests, 39 local-socket
  setup errors and one subprocess execution failure. These required permission
  to run temporary loopback servers/synthetic code checks outside the sandbox;
  they were not treated as successful tests.
- First implementation: 30/32 retrieval cases. Corpus-size-dependent BM25
  mixing could displace the compound match; score normalization and removal
  of generic query verbs fixed it. An existing identity regression also caught
  an overbroad `name` stopword, which was removed.
- New multi-hop/source tests caught missing deterministic project recognition
  and leakage of another typed project's attributes. Scoped first-person
  extraction and complete named-project anchors fixed both.
- First Chromium memory run exposed the narrower `Browserspiel`-only source
  case when queried as `Strategiespiel`. General concept-component matching
  fixed it; a dedicated unit regression guards against `Beispiel` contamination.
- Focused Memory Chromium rerun: **8 passed**, including DE/EN, mobile/desktop,
  source links, POST-only query transport, hostile stored HTML and pause.
- Full Python before the final resident guard: **4,172 passed and 472 subtests passed** in 78.51 seconds.
  JavaScript: **409 passed**; translation audit, dependency check and whitespace
  checks passed. The focused memory regression group is part of the full run.
- First full browser run: **119 passed, 13 setup errors** waiting for the
  ordinary chat composer to become visible in multi-reference/runtime-modal
  fixtures. The Memory-specific cases passed. These errors are investigated
  separately; this run is not reported as a green full-browser suite.
- Targeted repeat of all affected browser modules: **28 passed** in 47.93
  seconds. The startup failures did not reproduce. A clean full-browser rerun
  without concurrent Python load follows; no application or test threshold was
  changed to hide the failures.
- Final resource review found that the existing embedding proxy could load a
  cold model on a query. The foreground path now requires advertised resident
  support plus `require_loaded: true`; the proxy rejects cold requests before
  load admission or inference. The guard/routing/memory regression group:
  **127 passed and 2 subtests passed**. The real GPU behavior remains untested.
- Clean full Chromium acceptance: **132 passed** in 192.36 seconds, including
  all eight Memory browser cases. The earlier 13 composer-startup errors are
  retained above as observed failures, not removed from the record.
- Final full Python with resident-only embedding protection: **4,173 passed
  and 472 subtests passed** in 83.03 seconds. Public privacy scan: **1,226
  tracked files passed**. No new production dependency or schema migration.

## Open release gates

- Private archive completeness has not been inspected. A user-authorized local
  inventory/scan must check discovery completion and all error/stale segments.
- Real Qwen 4B extraction quality, 27B factual answer quality, hallucination
  rate, generated-answer abstention and citations remain **unmeasured in this
  change**. Retrieval/source metrics are not substitutes for those measures.
- No GPU/media-concurrency inference was performed. RAM/swap behavior on the
  real 48 GB system remains a separate acceptance test; process CPU RSS above
  does not measure unified GPU memory or swap safety.
- The independent, challenging semantic-model Recall@5 >=95% gate remains
  open. The fixed development fixture reaches 100%; broad linguistic coverage,
  arbitrary Hungarian indirect speech, aliases and named-entity ambiguity are
  not guaranteed by a small synonym vocabulary.
- Existing stored assertions are not automatically relabeled/revalidated by
  new filters. Complex quotations may be conservatively skipped. The dashboard
  does not retroactively invent a per-fact extractor/model identity for old
  records that never stored that metadata.
- Deployment and any private-history backfill require verified backups and
  separate approval. No production model test, history scan or restart was
  inferred from this implementation request.
